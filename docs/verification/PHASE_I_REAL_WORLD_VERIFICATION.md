# Phase I — Real-World Verification

Date: 2026-11-12 / 2026-11-13 · Branch `shahbaz_ai_vdeo` @ `3027636` (working tree clean; no production code changed during verification) · Hardware: RTX 3050 8 GB, Ryzen 5 7500F, 32 GB RAM, Docker Desktop (WSL2, 24 GB).

Method: the real stack (`docker compose up -d`, frontend `:3001`, backend `:8003`) driven in **Microsoft Edge through Playwright** (`playwright-core` with the installed Edge; no browser or model downloaded), plus direct API calls. All images and videos below were generated by the real models. Evidence is in `docs/verification/phase_i/`.

**Short verdict:** the pipeline works end to end (image, 5 s video, 30 s / 60 s / 120 s multi-scene videos, Plan scenes, scene editing, honest progress). **Prompt adherence is not good enough**: story prompts written in natural narrative form often collapse into a single scene, multi-character and background details are frequently wrong, and the user's own wolf/sheep video came out with no story progression and ghosting. Several of these are code bugs that can be fixed; some are limits of the 1.3B video model and SDXL.

## 5. GPU stability findings

- Clean start: video model 4.3 GB VRAM, peaks ~4.6–5.0 GB; no leak over 4 jobs; Windows uses ~0.8 GB.
- Backend container RAM reached **18.5 / 23.5 GB** with the image model (CPU-offloaded) and the video model (text encoder on CPU) both resident — close to the WSL limit.
- 2026-11-12, after ~5 hours of continuous jobs: VRAM 7.5–7.8 GB during jobs; one 120 s run hit `CUDA error: unknown error` (handled: `gpu_error`, restart, clips reused); later a 5 s clip stalled (VRAM 7.7 GB, GPU 0–17 %) and both containers exited (255). Not reproduced on 2026-11-13 from a clean start. Likely causes (unconfirmed): VRAM pressure from other Windows GPU apps plus the backend, and RAM pressure in the 24 GB WSL VM.
- The raw GPU sample files from these runs (`gpu_samples*.csv`), `restart_check.log`, the first `image_*` screenshots and the rabbit job snapshot **disappeared from the OneDrive folder around 14:28 on 2026-11-13** (cause unknown; no delete command was run). Their figures above come from the session output recorded at the time; `api_checks.log` and the images/videos were regenerated or re-downloaded.

## 8. Recommended fixes, by priority

1. **B1 — story splitting** (largest effect on "prompt not understood"): treat each sentence with its own subject + verb as a beat (names, `it`, any noun subject); recognise "Scene N:", numbered lists and line breaks; strip titles, quotes and "Moral:"; send each clip only its scene's characters. Add the rabbit, cat and wolf/sheep prompts as regression tests.
2. **B2 — no crossfade between independent clips**: use hard cuts, or generate each scene as one clip (≤ 5 s) by splitting longer scenes into sub-beats.
3. **B4 / GPU stability**: unload the image model fully (RAM as well as VRAM) before video; warn when free VRAM < 1.5 GB before starting; document closing GPU apps; investigate the stall with logging of free VRAM per clip.
4. **B3 — persist jobs** (SQLite) and list past generations in the UI; resume long videos after restart automatically.
5. **B6 — enforce the timeout** around text encoding and VAE decode as well.
6. **B5 — image default size** to the model's native 1024-class size; keep the count limitation visible.
7. **B7, B8, B9, B11, B12, B10** — small UI/text/cleanup fixes.
8. **R1** — re-test the retry button with a real failure once B6 is fixed (a short timeout will then fail reliably).
9. **Model limits (not fixable in code)**: exact counts, small details (hat colour, seagulls), multi-character identity and background detail are limited by Wan2.1/FastWan 1.3B and SDXL on 8 GB. Larger models (e.g. Wan 14B) do not fit this GPU.
